## 4. How work is done here (the orchestrator pattern)

The owner gives short requests and is usually not watching. The pattern that worked:

1. **Read** the docs above. If a request is ambiguous, pick a sensible interpretation, say it in one line, and go (the owner prefers action over questions).
2. **Shared foundation yourself** first (data model/types, migrations, export schema, version bumps, docs), merged before workers start, so parallel work doesn't conflict.
3. **Workers** (Agent tool, `isolation: "worktree"`, background) for independent features — one branch + PR each, with a precise brief: task, owned files, forbidden files, design decisions already made, tests, "don't edit DECISIONS.md (list decisions in the PR body)", "don't merge".
4. **Independent reviewer** agent per PR (didn't write the code): runs lint/typecheck/tests/web export, verifies rules by hand, Playwright at 375 and 1280 px, EN + DE. Forward findings to the worker via SendMessage. For sync-engine changes the reviewer works on its own copy (`git archive` + hard-linked `node_modules`), compares with `main`, reports only demonstrated sequences (a failing test), **and checks the fixes for its findings again before the merge** (§6).
5. **Merge** only with green CI (check `pull_request_read get_check_runs`). Squash when intermediate commits don't build.
6. **QA agent** over the acceptance checklist after a version's features are in.
7. **Docs**: add DECISIONS entries centrally (one PR), tick PLAN checklists, add the version to `docs/README_LEGACY.md` (Version history) and update the "What's new" line in `README.md`.
8. **Release** (§5), then report to the owner: link, what's new, what's verified, what isn't.

Small requests (layout tweaks) are faster done yourself; still use a branch + PR + green CI.

## 5. Releasing a version

1. Bump `version` in **both** `app.json` and `package.json` (e.g. 2.3.0) → `npm install --package-lock-only`. Android `versionCode` is derived (2.3.0 → 20300) in `app.config.js`, so the APK installs as an update.
2. Merge to `main` (CI green).
3. GitHub MCP: `actions_run_trigger` → `run_workflow`, `workflow_id: android-apk.yml`, `ref: main`, `inputs: {"release": true}`. It builds `volley-lineup-<version>.apk` (~25 min) and creates tag + release `v<version>`. It fails if that release already exists.
4. Confirm with `get_release_by_tag v<version>`.

**This session's git proxy cannot push tags** — always use the manual workflow run above (pushing `v*` tags only works from the owner's machine).

## 6. Gotchas learned the hard way

- **Installing packages**: the sandbox can't reach `api.expo.dev` → `EXPO_OFFLINE=1 npx expo install <pkg>`. Note new deps in DECISIONS.
- **RNTL v14 is async**: `await render(...)`, `await fireEvent.press(...)`. Route tests use `renderRouter` from `expo-router/testing-library` (set `useAppStore.setState({ hydrated: true })` first). Global Jest timeout 30 s.
- **Jest mocks** for worklets/Reanimated/RNGH are in `jest.setup.ts` (Reanimated 4.7 init stub) — don't add per-file hacks.
- **Worktrees** live in `.claude/worktrees/` (git-ignored; Jest/haste ignore it at the root only).
- **react-native-web ignores `accessibilityState`** → also set `aria-checked` / `aria-selected` / `aria-disabled`.
- **Zustand v5**: never return fresh arrays/objects from a selector without `useShallow`.
- **Persisted shape changes** need: store version bump + migration in `src/store/migrations.ts`, export `schemaVersion` bump + upgrade of old files in `exportSchema.ts`, the zod Same<> type guard, consistency checks, tests for v1/v2/... upgrades.
- **Played sets** (with live `events`) lock the lineup (#68); deleting a player in a played set is blocked (#73); presets/templates must not edit locked sets.
- **Emulator** (manual `android-smoke.yml`): AVD home must be pinned (`ANDROID_AVD_HOME`), boot can take > 10 min, the runner may run out of memory — don't gate PRs on it.
- **Merge conflicts in DECISIONS.md**: let workers list decisions in PR bodies; add them centrally.
- **Stop hook**: commit and push before ending a turn (untracked/uncommitted files trigger it). The session branch must be kept in sync with `main`.
- Agents' scratch files go in the session scratchpad, each in its own subfolder.
- **Parallel agents and git**: give every agent a unique local branch name (`review-pr40-$RANDOM`), never a shared one like `review` — worktrees share refs and one agent's checkout moved another's HEAD in v4.
- **Before committing on a branch an agent pushed to**: `git checkout -B <branch> origin/<branch>` can leave old files in the working tree; check `git diff --stat origin/<branch>` before `git add -A` (in v5 a docs commit silently reverted an agent's test rewrite).
- **Owner feedback can change the model**: v4 put roles on players, the owner wanted them on court spots (v5). For volleyball domain questions, check `docs/VOLLEYBALL_RULES.md` first and ask the owner one short question with options (AskUserQuestion) when the model itself is unclear.
- **Pre-wire shared files in the foundation PR** (i18n files per worker in `en.ts`/`de.ts`, new routes in `app/_layout.tsx` + `parentRoute.ts`, nav strings): it removed almost all merge conflicts between parallel workers in v3.
- **Before merging a PR whose base is behind `main`**: merge `origin/main` into its branch (in a scratch worktree), run the checks, push the merge commit, and merge only after CI is green on that SHA.
- **Header titles on web**: the header's title container doesn't shrink, so long titles overflow the page; `HeaderTitle` caps its own width — keep using it.
- **Branch names**: old feature branches still exist on origin (e.g. `feat/live-match` from v2) — pick new names; the git proxy can't delete remote branches.
- **Photo store order**: save a photo (`setPhoto`, in memory at once) before pointing a profile / player at it — the prune deletes unreferenced photos and clears `photoId`s without a photo on every profile / player change. Tests must seed `usePhotoStore` before `updatePlayer({ photoId })`.
- **Live screen height**: anything added to the live screen must keep the court + Substitution visible at 390×844 (DECISIONS #75, #126). The point-tag picker is the exception since v11 (#357): its chips wrap, because the owner could not scroll the old one-line picker on the phone.
- **A sideways ScrollView inside `NoTabSwipe` must be its direct child** (the blocker is a native gesture: around a plain View with the ScrollView further inside, the list did not scroll on the owner's phone — the browser showed nothing). Phone-only gesture faults don't show in Playwright or Jest: when something must be reachable, prefer showing it all over scrolling.
- **Panels without outlines show missing gaps**: siblings in a fragment have no distance. `scratchpad`-style scan used in v11: for every pair of filled blocks that don't contain each other, report a vertical or horizontal gap under 3 px (it found the season tabs, #358).
- **Agents and PR footers**: workers kept writing `_Generated by Claude Code_` footers — give them the exact footer and check it before merging.
- **Ids in URL params**: upgraded opponent ids contain "%" (`encodeURIComponent`); expo-router decodes params twice on web, so don't put such ids in URLs (#177).
- **Test helper** `seasonRefs(teamId, name)` (now in `src/test-utils/seasonRefs.ts`) creates a real season + opponent for `addMatch` in tests.
- **Styles go through `makeStyles`** (v8): a module-level `StyleSheet.create` with colours or text won't follow the theme or the dyslexia font. Name the factory parameter `theme` (`t` is the translation object).
- **Test the dyslexia font at 375 px in German**: OpenDyslexic is ~1.8× taller and wider; v8 needed font-only layout tweaks (#200). Check new screens with it.
- **Phone-only behaviour isn't visible in Playwright**: react-native-screens is off on web, so a navigator hiding scenes (`display: 'none'`) only shows on native — check with Jest (jest-expo runs as native) and read the navigator source; v8.1.1 nearly shipped a blank app-tab neighbour.
- **Web touch**: RNGH v3 `GestureDetector touchAction` has no effect with hook gestures — put `touchAction: 'pan-y'` in the gesture config (`SwipeTabs.tsx`), and test vertical scrolling with real touch (`hasTouch` + CDP), not only mouse.
- **PR footers**: the GitHub MCP / agents kept ending PR bodies with `_Generated by …_`; check and fix the body before merging (also in v8).
- **Label in name** (WCAG 2.5.3): an `accessibilityLabel` must start with the button's visible text — reviewers check this. A guard test (`__tests__/labelInName.test.tsx`) renders the app and checks every label (EN + DE).
- **Export golden** (`src/domain/__golden__/`): fixed input (t1 has captain p3 since v9.1) + v1–v9 files must export / import byte for byte; the export is schema 10 since v9.1. Only rewrite with `UPDATE_GOLDEN=1` for a real schema change; the folder is in `.prettierignore` (Prettier broke the byte match once).
- **Screenshot harness** `scripts/screenshots.js` (v12: 46 screens × 375/1280 × EN/DE × dark/light × font = 736 PNGs; it seeds the golden data, incl. its two hosted tournaments; `--compare` with ImageMagick AE). Proves "no visible change" for refactors; Settings shows the app version, so a version bump changes that line only.
- **Web QA with a fixed clock**: `page.clock.setFixedTime` makes every tap after a builder drag count as "just dragged" (`DragContext` compares `Date.now()`); move the clock forward between steps.
- **Tests run with no tour**: `jest.setup.ts` sets `tourMode: 'none'`; the screenshot harness seeds store v12 with `tourMode: 'none'`. With a fresh browser the first-start tour choice covers the screen.
- **Memoised domain results are shared**: copy before changing anything returned by `getMatchState`, `setStats`, `replay` & co.
- **Web export for browser QA: use `npx expo export -p web --clear`** — without `--clear` Metro can reuse a stale app manifest (old version, no `extra.supabase`), so sync looks unconfigured.
- **Supabase from the sandbox**: the host `qzeergfqfwovcvdarwua.supabase.co` had to be added to the environment's allowed hosts; the Supabase MCP tools are allowed in `.claude/settings.json` (`mcp__Supabase`). Every live schema change goes through a migration file in a PR; QA uses password test users (`supabase/tests/test-users.sql`) with sessions injected under `localStorage['sb-qzeergfqfwovcvdarwua-auth-token']`, never real code emails, and always runs the cleanup.
- **Free-tier auth limits**: the built-in mailer sends ~2 emails/hour — don't test sign-in by real email; use the fakes / test users.
- **The GitHub MCP `create_pull_request` replaces the PR footer** with its own `_Generated by_` line — check the body and fix it with `update_pull_request`.
- **Sync tests**: views that need a hold or members now also need a session in the runtime (`useSyncRuntime.setState({ session })`), because claims wait for the restored session (#289).
- **Engine scenario tests** (`TestDevice`): the devices share the global stores, so another device's cycle can't run inside one device's `act`. For "something happens on the server between this device's pull and push", wrap `b.backend.pullChanges` and write to the fake cloud through `cloud.device()` (a backend without a device), as in `photoRestart.test.ts`. A "restart" is: clear `engine.pendingPhotos` / `resetPending` and `setPendingRemotePhotos(new Set())`.
- **The Supabase connector can't run a file**: `execute_sql` takes the SQL as text. To run `supabase/tests/rls.sql` (1100+ lines) give a helper agent the file path and let it send the content; it must be one call (one transaction). **Test a migration before applying it** with a dry-run file: the test script with the migration spliced in after its `begin;` (ends in `rollback;`, no `commit`), then check that nothing is left (trigger / function counts). The script runs about 40 s (the 20 000-row limit test) and a connector call times out after 230 s; the connector may also ask the owner to confirm a call with deleting statements — when nobody answers, nothing runs (then run the changed test blocks directly, they are small). After `apply_migration`, set the recorded version to the file's (`update supabase_migrations.schema_migrations set version = '<file version>' where name = '<name>'`).
- **AFTER triggers fired by a foreign-key cascade run as the role of the outer statement**, not as the table owner (BEFORE triggers run inside the cascade as the owner). A trigger function that must work when `supabase_auth_admin` deletes a user needs `security definer`. `postgres` can't `set role supabase_auth_admin` on the hosted project, so this can't be tested there.
- **A proof on the live database without leftovers**: one `execute_sql` with `begin; … rollback;`, test users inserted into `auth.users` inside it, identities switched with `set local role authenticated` + `request.jwt.claims` (see the head of `rls.sql`). No email is sent. Inside one transaction `now()` doesn't move — make "earlier / later" explicit with an `update` of the timestamps.
- **The Supabase connector asks the owner to confirm any SQL that changes something** (DDL, `delete`, `revoke`, even inside a rolled-back transaction, and `apply_migration`). When nobody answers it times out after 230 s and nothing runs — and the tool then says not to call it again in that turn. Read-only `select`s go through. Plan database work for a chat where the owner watches (that is how `20261126140000` was applied), or give the owner the SQL-editor steps. The whole `rls.sql` (77 kB) is best sent by a helper agent that reads the file and makes the one call.
- **Force-push is refused here**: after a squash merge, bring the session branch up to date with `git fetch origin main && git merge origin/main` (stash first if needed) instead of resetting; the PR diff stays clean because the trees match.
- **ESLint in Jest** (`__tests__/eslintBackend.test.ts`): ESLint loads `eslint.config.js` with a dynamic import, which Jest refuses — pass the config with `overrideConfigFile: true, overrideConfig: require('../eslint.config.js')`, `@jest-environment node`.
- **`Constants.expoConfig` can't be replaced in tests** (non-configurable getter): change its `extra` object and restore it (`config.test.ts`).
- **One error text map**: every `SyncErrorCode` has its text in `t.sync.errors` only (the account / members / team-delete maps are gone). A new code needs EN + DE there (`satisfies Record<SyncErrorCode, string>`).
- **zustand's persist writes after every `set`**, also when the state is the same object: don't call the store for a no-op (AUDIT_V10 M19 is the engine's remaining case).
- **supabase-js (auth-js) deletes the stored session on any token-refresh error it doesn't list as temporary** (it lists 500–504, 520–530): anything else that is really an outage must reach it as a thrown network error (`authFetch.ts`). Test such things with the real client and a fake `fetch` (`authFetch.test.ts`, fake timers: it retries for up to 30 s).
- **Audit / review agents in the shared working tree**: tell them not to run state-changing git commands and to keep scratch files in the scratchpad; good ones work on a `git archive` copy. A worker that edits files in the same tree gets an explicit list of files it may touch and commits nothing.
- **A fix for a sync finding is not done until an independent reviewer has attacked the fix itself.** In the engine chat every first version of a fix was shown to lose data or get stuck in some sequence (11 sequences, 6 of them new with the fix), and one fix of a fix opened the opposite race. Brief the reviewer to compare with `main`, to report only what a failing Jest test shows, and send it the fixes again ("what I want attacked"). Undo each fix once (a mutation) to see its test fail.
- **What other devices do with half a push** (the reason for most of the push rules): a device that pulls a deleted season / opponent deletes everything below it that is older than the deletion, without tombstones, and a match row that arrives later without its sets is skipped as an orphan for good; two seasons / opponents of the same name are merged by `repairSlice` on every manager device, which then pushes the newer one's deletion. So: parents before children, a new match with its sets in one request, and the deletion of a season / opponent in one request with the new or changed seasons, opponents and matches the cloud has (`together`). Never "send deletions last" or "send them first".
- **A held-back record must not let something else go that depends on it**: new records below a held new record wait; season / opponent deletions wait while a change of a match (or opponent) the cloud has waits. The device doesn't know which season / opponent the cloud's copy is under (`base` has no payload), so the rule is blunt on purpose.
- **Mutation runs can hang**: a mistake in the push loop spins without ever yielding to Jest's timeout. Run mutations through a script with its own timeout that restores the file in `finally` (and check `git status` afterwards). The push loop itself now ends after `8 × changes + 16` refusals.
- **A local PostgreSQL 16 is in the cloud container** (`/usr/lib/postgresql/16/bin`; `initdb` + `pg_ctl` as the `postgres` user with `runuser`, a throwaway directory and a socket-only port): use it to check an SQLSTATE or a query without touching the live project (how 22P02 for half an emoji was confirmed).
- **Jest's fake timers stall Node's streams**: tests of the response-body timeout run on real time with a short limit (`fetchWithTimeout.test.ts`).
- **"Restart" in a two-device scenario test** = clear the engine's in-memory state for that device (`pendingPhotos`, `lostPhotos`, `checkedFolders`, `awaited`, `refused`, `unsent`, `yielded`) or build a new `TestDevice` on the same data; the devices share the global stores and take turns through `act`.
- **Several PRs in a row from one session branch**: squash-merge, `git fetch origin main && git merge origin/main`, bring the next commits over, one commit, full check, push, new PR. `create_pull_request` (GitHub MCP) replaces the body's footer — set the body again with `update_pull_request`; `merge_pull_request` wants the full 40-character head SHA.
- **Take-over rule (`yieldedMatches`)**: a device that yielded keeps yielding until it _sees_ the other hold gone (a hold list without it, or it takes the match back). Don't "fix" the offline case by passing `yieldedNow(core)` into `setHolds`: that loses the new scorer's rallies when it kept scoring (AUDIT_V10 "Open questions" 11).
- **Looking at screenshots cheaply (v11)**: the shots are 375 × 1400, so a bottom bar is far below a "top 900 px" crop — crop from the bottom (`-gravity south`) to see it. Contact sheets with ImageMagick `montage … -crop x900+0+0 +repage -resize 60% -tile 8x` show eight screens in one image; a before/after pair is two rows. Export once, shoot once per pull request (`--only <name>` re-shoots a few screens into the same folder after a small fix). Don't edit files while `expo export` runs: the build reads the working tree.
- **Measuring instead of guessing (v11)**: a small Playwright script that prints `boundingBox()` of a test ID at 390 × 844 (EN / DE, font off / on) on the old and the new build settles "is it still on the screen" in a minute; `react-native-web` turns `testID` into `data-testid`.
- **German decides the layout**: five link tiles fitted across 375 px in English and not in German ("Aufstellungen", "Drucken / PDF"). The web has no `adjustsFontSizeToFit`, so text there is cut, not shrunk — make it fit at its base size, and check DE (and DE with the dyslexia font) before settling a row of equal boxes.
- **A header option's render function runs twice on phones**: once for `AppHeader`, once for the native stack's hidden header. Wrap it in `appHeaderOnly()`; a test that finds "multiple elements with testID header-back" means one was forgotten.
- **The navigator's `tabBar` props here are `{ state, descriptors, emitter, navigateToTab, insets }`** (expo-router's vendored bottom tabs), not React Navigation 7's `navigation`.
- **The Reanimated mock reads a shared value when the component renders**: after changing a prop that moves something, render once more before asserting the animated style (`v11Motion.test.tsx`).
- **react-hooks lint refuses `setState` in an effect**: derive it (`const placed = itemWidth > 0`) and keep "first time" in a ref.
- **A label must follow the order shown** (`labelInName` guard): when the kind moved above a season's name, its accessible name had to start with the kind too.
- **`TransferData` must not grow** (v12): `src/domain/syncImport.ts` builds `TransferData` literals, so a new required field there breaks the typecheck in code that must not be touched. Data that isn't a team's goes beside it, like `HostedData` (#364).
- **A store version bump re-pulls every shared team once** (`migrations.ts`, audit L6): intended, but say so in the pull request of any stored-shape change (#371).
- **`resetStores()` keeps the device settings** (like "Delete all data"): a test that sets `language: 'de'` leaves it for the next test — set `language: 'en'` in `beforeEach` (v12 lost an hour of confusing failures to this).
- **Layout checks are a script now** (`scripts/layout-scan.js <dist> <routes…>`, v12): controls under 44 px, filled panels that touch or overlap, sideways scrolling, text cut without "…", at 375 px in EN / DE with and without the dyslexia font. A long screen under the pinned tab bar reports its rows as touching the bar; that is scrolling, not a fault.
- **Rows that hold a line of facts** ("6 teams · 8 of 15 played", "3 played · 2–1 · sets 5:2 · balls +41"): at 375 px beside two icon buttons, or with the dyslexia font, one text gets cut. Draw the parts as separate one-line texts in a wrapping row (`TournamentRow`, `TournamentTable`).
- **Two options whose text is a sentence don't fit a two-segment track in German** ("Alle Sätze werden gespielt"): stack them (`StackedChoice`).
- **`create_pull_request` replaces the body's footer; `update_pull_request` doesn't**: create with a one-line body, then set the real body once with `update_pull_request`.
- **Golden input and tests**: `src/domain/__golden__/input.json` is also what `seedGolden()`, the label guard and the screenshot script use, so adding data there gives all three the new screens' content. Append to the file by hand; re-dumping it reformats the hand-set arrays.

## 7. Checklist for starting a new version

- [ ] `/start` → read docs, `git fetch origin main`, `npm ci`, run `npm run lint && npm run typecheck && npm test`.
- [ ] Write the version's plan into `docs/PLAN.md` (new section with features, data model changes, acceptance checklist).
- [ ] Foundation PR (types/store/export migrations + version bump if the data shape changes).
- [ ] Workers → reviews → merges → QA → fixes.
- [ ] DECISIONS + `docs/README_LEGACY.md` version history + `README.md` "What's new" + PLAN ticks → release (§5).
- [ ] `/wrap-up` before the chat ends.
